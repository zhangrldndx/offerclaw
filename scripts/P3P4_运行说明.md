# P3/P4 异机运行包 · 使用说明(大白话版)

## 这是什么

两个被原机器(GPU 事故+性能不足)推迟的实验,拿到更强的机器上跑:

| 实验 | 干什么 | 预计耗时 |
|---|---|---|
| **P4 延迟-精度扫描** | 精排候选数扫 5/10/20/40 四档,每档测检索准确率(两套冻结评测集)+ 逐题延迟 p50/p95,画"延迟 vs 精度"权衡曲线的数据 | GPU 上 ~20-40 分钟 |
| **P3 规模压测** | 用真实句子池合成语料,把向量库灌到 1万/5万/10万块,测检索延迟怎么涨、内存吃多少、拐点在哪;测完自动删临时集合 | 视机器 1-3 小时(嵌入 16 万块是大头) |

## 怎么跑(三步)

```bash
# 1. 解包(两个包解到同一目录)
mkdir offerclaw_run && cd offerclaw_run
tar -xzf offerclaw_src_snapshot.tar.gz         # 源码（锁定到离线快照）
tar -xzf offerclaw_chroma_db.tar.gz            # 向量库(162MB,3340 chunks)

# 2. 一键跑(自动建 venv、装依赖、自检、串行跑 P4→P3、打包结果)
bash scripts/run_p3_p4.sh

# 3. 把生成的 results_p3p4_主机名_日期.tar.gz 拷回原机器,交给 Claude
```

## 注意事项

1. **不需要任何 API key**——评测的核心判定(检索排名/拒答)纯靠本地模型;没 key 只是"答案文本"环节降级,不影响任何指标数字。仓库里也没有打包任何密钥。
2. **首次运行会联网下载两个模型**(bge-base-zh-v1.5 + bge-reranker-base,约 1.2GB,走 ModelScope 国内源);之后离线可跑。
3. **设备**:脚本自动用 CUDA(N 卡)> MPS(Mac)> CPU,并把设备信息写进结果包——**延迟数字必须带设备标注才有可比性**,这是本项目的口径纪律。
4. **别并行跑两个实验**(P3 嵌入 16 万块会吃满算力;脚本已内置串行)。
5. 机器内存建议 ≥16GB(P3 的 10 万块档 + 模型常驻)。
6. 出问题就把 `/tmp/p4_*.log` `/tmp/p3_*.log` 一起拷回来,日志能定位。

## 结果怎么被使用

拷回后 Claude 会:①校验 JSON 完整性与设备标注;②出两张图(延迟-精度权衡曲线 + 规模-延迟曲线,标注拐点);③回填 `docs/rag_eval/round9/REPORT.md` §5-§7 与 metrics.json;④给出"1.3 秒是选择不是极限"和"10 万级拐点在哪"的面试话术。
