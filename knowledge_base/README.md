# OfferClaw 知识库使用指南

本目录存放**外部岗位知识**(语料层),供 RAG 检索使用;与项目内部文件(profile/log/prompt 契约,它们由固定清单直接入索引)互补。

> **入库的唯一判定标准**:ChromaDB 索引(`chroma_db/`)里有没有该文件的块。
> 文件躺在本目录 ≠ 已入库;全量重建(`python rag_ingest.py --rebuild`)只认下方"正式子目录"+根级固定清单,`_pending/` 永远不进索引。

## 目录结构

```
knowledge_base/
├── career_paths/          # 岗位路线(source_type=career_knowledge)：技能树、学习顺序、能力模型
├── experience_posts/      # 经验贴(experience)：真人分享的转行/求职/学习经验
├── learning_resources/    # 学习资源(resource)：八股、教程、课程、项目、书籍——问答与规划检索的主力
├── project_context/       # 已有项目先验(project_context)：如 LocalFlow 现状,规划"在现有项目上推进"的只读上下文
├── _pending/              # ⚠️ 采集管道暂存区——永不入索引,别手动往里放文件
│   ├── web/               #    待审候选(URL 抓取 / UI 上传落这里,带打分元数据)
│   ├── _archived/         #    归档区(审核后判为"已在库副本"的候选移入,即从待审列表消失)
│   └── <其他>/            #    doc2kb 等采集工具的中间产物
└── README.md              # 本文件(不入语料)
```

## 两条入库途径(都要经 UI 预览审核)

### 途径 A · 文件夹直投(适合:自己整理好的 .md 笔记)

1. 把 **.md 文件**直接放进上面任一**正式子目录**(按内容选目录,source_type 自动按目录推断);
2. 打开 Web UI → 知识库卡「待审候选」展开 → 底部「📂 文件夹直投·未入库」会列出它;
3. 点「预览」卡内阅读(或「在访达中显示」)→ 确认无误点「入库」→ 文件不动,原地增量建索引。

### 途径 B · 管道采集(适合:URL 文章、PDF/Word、想先打分暂存的内容)

1. UI 粘贴 URL「抓取入候选」,或「上传 md/txt/pdf/docx」(PDF/Word 由服务端抽取文字;**扫描版/图片型 PDF 无文字层,会明确拒绝**,请先转文本);
2. 内容经密钥脱敏 + LLM 质量打分(A/B/C 档),落 `_pending/web/` 成为**待审候选**;
3. UI「待审候选」列表点「预览」审核 →「选它」归类 →「确认入库」= 文件移入所选正式子目录 + 增量建索引。

### 三条铁律

1. **自己的 md → 正式子目录(途径A)**;URL/PDF/Word → UI(途径B)。
2. **永远不要手动往 `_pending/` 放文件**——候选列表只认管道写入的打分元数据(frontmatter `source_url`),手放的裸文件不会出现在任何列表(黑洞)。
3. 候选带「疑似已在库」标记(与正式子目录同名/同标题比对)= 大概率是历史遗留副本,预览核实后移入 `_pending/_archived/` 归档,不必再入库。

### 怎么区分一个待审文件来自哪条途径

看它出现在哪个分组:「待审候选」列表 = 途径B(预览路径以 `_pending/web/` 开头,带打分档);「文件夹直投·未入库」= 途径A(路径就是正式子目录)。

## 文件格式要求(正式子目录内)

每个 .md 建议以 YAML frontmatter 开头(途径B 自动生成;途径A 手写可选,但写了标题检索更准):

```yaml
---
title: 文章标题
source_url: https://原始来源URL（自己写的填 original）
crawl_date: 2026-06-02
quality: A           # A=高质量干货 B=有参考价值 C=一般
target_role: 大模型应用工程师
tags: [关键词1, 关键词2]
---
```

正文用标准 Markdown,建议按主题分 `##` 小节,便于 RAG 分块检索;`_` 前缀文件名不会被扫描。

## 质量标准

- A 级:有具体技术细节或可操作步骤,作者有实战背景
- B 级:方向正确但偏概述,或部分内容已过时
- C 级:有参考价值但信息密度低,仅作补充(用户主动上传的即便判 C 也保留候选,尊重"自己选的资料")
