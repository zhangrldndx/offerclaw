## 完整版（技术岗 / 大模型应用工程师方向）

**OfferClaw · 长期养成型求职 AI Agent（个人项目）**
`Python · RAG · LangGraph · ChromaDB · bge 向量/重排 · BM25`

> 面向「大模型应用工程师」岗位的求职 Agent：知识库问答、岗位匹配、学习计划、简历工坊、每日复盘的完整闭环；微信端长期陪伴式养成。

**RAG 检索系统（核心，12 轮量化迭代）**
- 主导 RAG 检索从朴素向量检索到生产级的 **12 轮迭代优化**，先建可信评测体系（**100 题同分布 + 52 题口语 held-out** + Recall@1/3/5 / MRR + 拒答门槛 + 答案质量），让每步优化可归因；同分布检索 **R@1 89% / MRR 0.922**，真实口语 **R@1 50% / MRR 0.566**，答案忠实度 **8.83**（中立交叉评审，主动披露同分布高估）
- 实现 **BM25 稀疏 + 向量稠密 + RRF 融合** 混合检索，解决同主题多源召回，llm_app 域 **R@1 +5.6pt**
- 集成本地 **bge-reranker 交叉编码器**两阶段精排（粗召回 → 精排），难题 **R@1 82%→91%**
- 设计**元数据/文件名感知路由**，解决向量 / BM25 / rerank 三者都无解的「95% 同质文档」区分（如「算法岗 vs 后端转型」），career 域 **R@1 75%→100%、零副作用**
- 构建**距离 + reranker 双证据拒答门控**（「相似 ≠ 相关」，cross-encoder 持否决权），gate 负样本拒答 **12/12**、边缘误判拒答率 **+25%**
- 定位“排序命中不等于回答可用”：跨语言正确 Top1 被中文距离门拒绝；以 50 正例 + 60 负例标定英文证据门 **τ=0.80**，只给英文候选接 113MB mMiniLM ONNX 分工桥。显式论文入口端到端 grounded 正确 **11→30/50**、错误放行 **0**，p95 **589ms**；全量多语模型虽更快但使中文基线 **86%→77%**，据 A/B 主动否决

**LLM / Agent 工程化加固（12 项 + CI）**
- 把检索侧的弹性容错**系统复刻到生成 / 编排 / 记忆 / 工具全栈**：统一 LLM 网关（智能重试 + 退避 + 降级，6 处裸调用收口）、DAG 节点 fail-soft、记忆原子化 + 损坏可恢复、工具墙钟预算；用**故障注入测试**量化（注入 429 / 超时 / 畸形 tool_call / 损坏文件 / 工具卡死），新增 **47 个测试 + CI 门禁**防回归

## 写简历的注意点（面试官视角）

1. **数字必须可追溯**：每条量化都对应 `docs/RAG_OPTIMIZATION_LOG.md` / `AGENT_OPTIMIZATION_LOG.md` 的某一轮，面试被追问时能立刻翻出「怎么测的」。**编不出来的数字别写**。
2. **突出「判断」而非「技术名词堆砌」**：「元数据路由解决向量都无解的同质文档」比「用了 RAG」有信息量——体现你能定位瓶颈在哪一层。
3. **HyDE 证伪可以主动提**（面试聊到时）：「我还试了 HyDE，实测判定有害并保留为对照」——敢说失败方案、且分析透原因，比只报喜可信。
4. **英文版**：投外企 / 英文 JD 时需要，需要的话我转一版（关键术语 RAG / RRF / cross-encoder / fault-injection 直接用英文）。
