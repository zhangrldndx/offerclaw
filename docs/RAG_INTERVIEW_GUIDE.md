# OfferClaw RAG 项目 · 面试讲解指南

> 把八轮 RAG 优化整理成**可直接讲**的项目故事。配合 `RAG_OPTIMIZATION_LOG.md`（逐轮实证）食用。
> 讲解原则：**先讲判断、再讲技术、用数字收尾**。面试官要听的是工程思维，不是术语堆砌。

---

## 一、30 秒电梯陈述

> 我给一个长期养成型求职 Agent 做了 RAG 检索系统的端到端优化。从一个「只有向量检索 + 宽松评测」的朴素版本，
> 用 **8 轮迭代**做到了**召回 / 排序 / 同质区分 / 拒答 / 生成全链路闭环**，每个环节都有量化标尺。
> 核心不是堆技术，而是**先建可信度量、再让每个优化匹配真正的瓶颈**——包括一个**主动证伪、判定无效**的方案（HyDE）。
> 最终检索 R@1 从基线提升到 86%、MRR 0.913、拒答准确率 12/12，答案忠实度 8.83/10（中立交叉评审 deepseek-v3；自评 9.92）。

## 二、项目故事（STAR）

- **S 背景**：知识库是大模型应用工程师的面试八股 + 真实项目文档（3299 块，多源）。原系统只有「向量 top-5 + 距离阈值」，
  评测还是「命中本域任意文件即算」——显示 100% 召回，**毫无区分度**。
- **T 任务**：把检索质量做到可量化、可持续优化，并保证「答案不幻觉、不相关的问题能拒答」。
- **A 行动**（8 轮，每轮：选瓶颈 → 改代码 → 前后量化 → 对应知识点）：
  | 轮次 | 做了什么 | 解决的瓶颈 |
  |---|---|---|
  | R0 | 重建评测：精确到目标文件 + Recall@k/MRR/gate | 度量不可信 |
  | R1 | 本地 bge-reranker 交叉编码器精排 | 「语义相似 ≠ 最相关」 |
  | 真实化 | 多源仓库入库 1024→3299 块 | 评测虚高、不真实 |
  | R2 | BM25 + 向量 + RRF 混合检索 | 同主题多源召回不全 |
  | R3 | HyDE 查询改写 → **证伪** | （误判瓶颈在 query 侧）|
  | R4 | 文件名元数据感知路由 | 95% 同质文档分不开 |
  | R5 | gate 阈值随库规模重标定 | 扩库后拒答退化 |
  | R6 | reranker 二次确认（双证据门控）| 正负距离分布重叠 |
  | R7 | RAGAS 风格答案质量评测 | 只评检索、没评生成 |
- **R 结果**：检索 R@1 89 / R@3 96 / R@5 98 / MRR 0.922、gate 12/12+12/12；答案忠实度 8.83 / 完整 8.0 / 引用 8.5（deepseek-v3 交叉评审；自评 9.92/9.42/10.0）。

## 三、面试高频 QA（答案要点 = 讲解骨架）

**Q1. 这个 RAG 项目你具体做了什么？**
> 端到端优化检索栈：混合检索召回 → 交叉编码器精排 → 元数据路由 → 双证据拒答门控 → grounded 生成。
> 关键是**先把评测做对**——否则优化是自欺。

**Q2. 为什么要做这么多轮，而不是一步到位？**
> 因为**不知道瓶颈在哪之前，优化是赌博**。我每轮只动一个变量、前后量化，让每步提升可归因。
> 这也帮我抓出一个「看起来该有用、实测有害」的方案（HyDE）。

**Q3. 混合检索为什么是 BM25 + 向量 + RRF？RRF 是什么？**
> 向量（稠密）擅长语义但会漏精确关键词；BM25（稀疏/词法）按词频精确匹配术语，两者互补。
> **RRF（倒数排名融合）**：score(d)=Σ 1/(k+rank)，k=60，只看排名不看绝对分，避免两路分数尺度不一致。
> 实测对「同主题多源」的中文关键词题，llm_app R@1 +5.6。

**Q4. rerank 和向量检索的区别？为什么需要 rerank？**
> 向量是**双塔**——query 和 doc 各自编码再算距离，信息有损，「相似 ≠ 相关」。
> rerank 是**交叉编码器（cross-encoder）**，query+doc 拼一起过模型，精判相关性，但慢。
> 所以用「向量粗召回 N 个 → reranker 精排 top-k」。难题 R@1 从 82 提到 91。

**Q5. 同质文档检索分不开怎么办？（亮点题）**
> 我遇到 career 域三个文件 95% 雷同（零基础/后端/算法转型），唯一区分点是「目标人群」。
> 向量、BM25、rerank **全分不开**——因为区分词被大量重叠词淹没。
> 解法在**文档侧**：文件名已编码人群（zero_foundation/backend/algorithm），做元数据感知路由，按 query 人群词精确区分。
> career R@1 从 75 打满到 100，零副作用。**关键判断：方法要匹配瓶颈所在的层。**

**Q6. 拒答（不相关问题）怎么做？为什么双证据？**
> 先用距离阈值（向量 best 距离 > 阈值 → 拒答）。但扩库后发现**正负样本距离分布重叠**——
> 有些边缘词（如 Docker，KB 里沾边）距离很近却不该答。
> 所以加**第二重正交证据**：reranker 相关性分。距离判「相似」、reranker 判「相关」，reranker 持否决权。
> 边缘误判拒答率 +25%，正常题零影响。

**Q7. RAG 怎么评测？检索和生成分别怎么评？**
> **检索**：精确到目标文件的 Recall@1/3/5 + MRR + 拒答门槛（正/负样本各一组）。
> **生成**：RAGAS 风格 LLM-as-judge，三维度——忠实度（答案↔检索资料，防幻觉）、完整度、引用准确性。
> 忠实度 8.83（中立）说明 grounded prompt「严禁资料外知识」约束有效。

**Q8. 遇到的最大坑 / 印象最深的是什么？（必问，体现深度）**
> HyDE（假设性文档嵌入）。理论上该提升模糊查询，但我实测**无效甚至有害**：
> ① 评测 query 已含精确关键词，鸿沟本就小；② 真正瓶颈在文档侧（同源挤压），query 侧治不了；③ 每查询一次 LLM、延迟大。
> 这让我明白**方法要匹配瓶颈所在的层**——这比「又涨了几个点」更有价值。**负结果也是成果。**

**Q9. 怎么保证你的评测/数字是可信的，不是过拟合？**
> 三件事：① 评测精确到目标文件（不是本域命中即算）；② 知识库真实化——单源库 R@5 虚高 100%，
> 加多源交叉后才回落到真实区间；③ 阈值标定后**扩充评测集翻倍验证**（gate 6→12 仍满分），
> 而且诚实记录了「评测集越大、正负分布越重叠」这个纯阈值的固有局限。

**Q10. 这个系统还有什么不足 / 下一步？**
> ① 泛开放问题（如「学习路径怎么规划」）答案不够 grounded，检索 chunk 散；
> ② 个别边缘词（reranker 也误判的）需要第三重证据如关键词覆盖度；
> ③ llm_app 部分失分其实是「新入库内容比旧标注更好」，需要评测标注随库演进治理。

## 四、技术选型理由（被追问时用）

- **为什么本地 bge 而非 API embedding**：成本 + 隐私（个人求职数据），bge-base-zh 中文够用，3 域满分。
- **为什么 RRF 而非加权求和**：两路分数尺度不可比（向量距离 vs BM25 词频分），RRF 只用排名、免标定。
- **为什么元数据路由而非重新训练/微调**：文件名已天然编码人群，零训练成本、零副作用、可解释。
- **为什么 LLM-as-judge 而非 BLEU/ROUGE**：八股问答没有唯一标准答案，字面匹配无意义，要评语义忠实度。

## 五、踩坑与解决（每个都体现判断力）

| 坑 | 现象 | 解决 / 教训 |
|---|---|---|
| 评测虚高 | 旧评测显示 100% 召回 | 命中本域即算太松 → 精确到目标文件 |
| 库太干净 | R@5=100% 不真实 | 单源 96% → 多源交叉，逼近工业真实 |
| HyDE 有害 | 救 career 反而更差 | query 侧治不了文档侧瓶颈，**证伪并保留为对照** |
| 阈值过拟合 | 小样本完美分离 | 扩充评测集翻倍验证；揭示纯阈值固有局限 |
| 负样本沾边 | Docker/React 误判 | 选负样本必须 grep 验证 KB 零覆盖 |
| 标注过时 | 检索对了却判错 | 库升级后 ground truth 要随之演进 |
